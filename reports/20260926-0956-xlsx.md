## 效果结论：**留用**（在「交付物是表格/模型」这一类里是当前最强的一份规范）

99 行讲清了建一个能给别人改的工作簿的全部纪律，且**几乎每条都能被证伪**——本轮 49 条断言里有一条正是被它救回来的：`=H/60` 遇到空耗时单元格**不报错、静默返回 0.0**（E4 独立复现），于是 `IFERROR` 完全不会触发，一个 15 分钟没人会看的模型会带着「第 8 轮平均 0.0 分钟」这样的合法假数交付。这条坑它用「guard denominators」点到了边，但没点到「空单元格被当 0」这个具体形态——补上守卫 `=IF(H="","",H/60)` 后 C6/S 类断言才全绿。

局限：**闸门强度取决于有没有 LibreOffice**。没有 `soffice` 就得不到技能自己的 `recalc.py` 输出（`status/total_errors/error_summary` 那份 JSON），验证得自带第三方引擎——本轮换到的 `formulas` 是纯 Python、aliyun 镜像 30 秒装好，但它**不等于 Excel 也不等于 LibreOffice**，函数覆盖不同（见 E2/E3），因此它给的「0 error」只证明公式在第三方语义下可解析。

## 踩的坑（含对技能声明的证伪）

1. **`recalc.py` 在本机不可用**：308 行脚本 100% 绑定 `soffice`（`SOFFICE_MISSING = "soffice not found on PATH..."`），`scripts/office/soffice.py` 的 LD_PRELOAD shim 是给 Linux 沙箱解 AF_UNIX 限制的，装不上 LibreOffice 就完全跑不到。技能正文把 recalc 写成「mandatory whenever the file contains formulas」，所以**这份技能隐含要求一台装有 LibreOffice 的机器**；无人值守流水线里要么先探测 `which soffice` 再决定是否选它，要么自带替代引擎（本轮：`formulas`）。
2. **★E2/E3：它的 `_xlfn.` 前缀条款是运行时特定，不是函数真理。** 独立引擎实测：`XLOOKUP(2,A1:A3,B1:B3)` → `'y'`（正常值，非 `#NAME?`）；`TEXTJOIN` 裸写 → `'x,y,z'`（算对），而**加了 `_xlfn.` 前缀反而失效**（返回未解析的公式串）——与它对 Excel 生态的告诫**正好相反**。原因也说得通：`_xlfn.` 是 Excel 存储层命名，LibreOffice/Excel 认，第三方解析器不认。结论：写「要给 Excel/LibreOffice 打开」的文件时按它的清单办（本轮全照做，禁 XLOOKUP/FILTER/SORT/UNIQUE、不用前缀函数），但**不要把这份清单当成通用真理**去审其它引擎的产物。
3. **技能自带的 `scripts/office/validate.py` 不覆盖 xlsx**：只有 `validators/{docx,pptx,redlining}.py`，XSD 目录里虽有 `sml.xsd`，但没有 xlsx 校验器 → 「跑它的 checker」这一步对本技能是空的。（延续第 5/6 轮结论：市场/仓库包的实现层完整性必须自己 `find` 核对；本轮补一条——即使文件齐全，也可能对你要做的文件类型无覆盖。）
4. **「绿了不等于对」在本轮以 Twice 命中，且都是我自己造成的**：
   - 第 1 版 `Metrics` 分组「平均耗时」用 `SUMIF(...)/COUNTIF(分组)`，把第 8 轮的空耗时当 0 计入分母 → 本机已装组算出 **6.5 分钟**，真值 13.0。而这条当时**通过了**断言，因为我 C23 只比对了 3 列里的 2 列（判据覆盖不全）。改 `COUNTIFS(...,">0")` 并把第三列纳入断言后才闭合。
   - 第 1 版把「公式口径」文档列写成以 `=` 开头的字符串 → openpyxl 把它当**活公式**写进 XML，等于给每条被记录的公式又造了一份可执行副本（公式数 98→122）。修法：赋值后 `cell.data_type = "s"`，产物里落成 `t="inlineStr"`，并补 S9 断言盯住。
   - 另有 2 条纯判据错：`MAX+MATCH` 我预期 `ppt-generator`（14/14），但 `algorithmic-art` 20/20 同为满分且行在前，MATCH 取首个是正确行为；以及 `openpyxl` 读回的字体色是 `000000FF` 而非 `FF0000FF`，颜色断言要 `endswith("0000FF")`。
   - **规律**：断言要按**被测对象的完整维度**写（三项分组就三条都查），且「全部 FAIL / 一次全绿」都先怀疑判据；技能自带的 checker 全绿永远要再叠一层独立断言（第 5 轮 ppt-generator 的 `svg_quality_checker.py` 同一教训）。
5. **台账 schema 漂移被抓到**：`state.json runs[]` 从第 5 轮起不再写 `installed_by_this_task`（第 1–4 轮有），若按 runs 取数，本轮 `新装技能数` 会得 2 而非 5。已改从 `tried[]` 取并**回填 runs[5..8]**。这正是「产物逼着台账自证」的收益——以后 `measure.py` 类脚本读台账要先做字段完整性检查。
6. 环境：`python3 -m pip install --target .tmp/pylibs --index-url https://mirrors.aliyun.com/pypi/simple/ openpyxl formulas` 29.7 秒，但**体积 218MB**（`formulas` 拉进 scipy + numpy + schedula + regex + tqdm）。产物只 15KB → 收尾必删 `.tmp/pylibs`；只装 `openpyxl` 是 ~2MB 量级，下次若不为重算就单装 openpyxl。
7. macOS 无 `timeout` 命令（`command not found: timeout`）→ 需要限时就 `python3 -c` 里用 `subprocess(timeout=)` 或 `gtimeout`（coreutils）。
