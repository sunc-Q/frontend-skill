## 验证结论：26 PASS / 0 FAIL

- **B 组（自己手写 GIF 二进制解析器，不用库）**：GIF89a、逻辑屏幕 800×800、48 个 GCE/图像描述符对 == `floor(4.0×12)`（Critical Rule 6 兑现）、NETSCAPE2.0 loop count = 0（无限循环）、帧 0 全画布 + 13 种差分矩形全部在画布内、帧延迟集合 ⊂ {8,9} 且均值 8.33（= 100/12）。
- **C 组（Critical Rule 5「WAAPI 寻址而非 setTimeout」的直接反证）**：48 帧 `--num` 单调不降 0→6、`counterReset` 与注册属性值 48/48 一致、t=1.67s 仍为 4 而 t=2.42s 已锁定 6（hold 烘焙生效）、stats 淡入门限在 45% 关键帧、光标 0/1 两态。
- **D 组（像素 ↔ 计算状态交叉核对）**：48 帧全精度状态 = 22 个不同状态、**0 组"同状态异像素"** → 逐帧寻址是位级可复现的；帧 0 与帧 47 的 md5 不同 → 接缝不重复；20 个不同帧哈希。
- **D4 编码器无关核对**：`ffmpeg -i animation.gif -f null -` 回读 `frame= 48 time=00:00:04.00`。
- HTML 侧 9 条按它 Step 4 自检清单逐条落断言（800×800、双 overflow:hidden、零 animation-delay、fill-mode、迭代次数、@property 声明、counter-reset/::after、零外链、扫描线 0.03）。

## 效果结论：**留用（当规格书用，别当工具用）**

它的规则层是**可证伪且写对了的**：Rule 5（寻址而非 setTimeout）、Rule 6（不捕获 t=duration 以免循环点抖动）、Rule 9（stagger 烘焙进关键帧）三条一旦照做，产物第一次就通过全部 26 条断言——这三条比多数"生成图表"技能的具体。加上它自带 12fps/4s 的量级与 email<500KB / social<3MB 的体积门槛，是一份能直接验收的 CSS→GIF 规格。
留用的前提是本机自己补三件它没给的东西：**导出脚本、动画类型库、风格预设 token 表**（见坑 1）。若只装包不实现，等于什么也跑不出来。

## 踩的坑（按重要度）

1. **★包内只有 SKILL.md，实现层 100% 缺失。** SKILL.md 明文要读 `references/animation-library.md`（6 种动画的完整 HTML/CSS 规格）、`references/style-presets.md`（4 套预设的 CSS token）并执行 `bash [skill-root]/scripts/export-gif.sh`（内部跑 `capture-and-encode.mjs`）——**四个文件在包里都不存在**（`find` 结果只有 SKILL.md 12225 字节）。这是本市场包第 3 次同一缺陷模式（第 2 轮 ascii-project-dashboard 的 muscle script、第 4 轮 SQLite 专家的 references/*.md），已基本可判定为**该市场镜像的系统性问题：只搬 SKILL.md，丢 scripts/ 与 references/**。→ 后续任何市场技能装完第一步 `find <skill> -type f` 核对文件清单，别信它写的路径。
2. **★本环境其实能真截图，之前五轮的"只能靠计算样式"是被误限的。** 前几轮结论「IDE 浏览器面板 hidden、take_screenshot 不可用 → 只能用 getComputedStyle/离屏容器代替」只适用于 browser-use MCP。本轮证明：`/Applications/Google Chrome.app` + `playwright-core`（不下载浏览器，`executablePath` 直指系统 Chrome）可以**按 800×800 定宽真截图**，48 帧端到端 7 秒；`~/.local/bin/ffmpeg` 还在。→ 以后任何 HTML 产物都能做**像素级**验证与真出图，不必再搭离屏容器绕路。这是本实验室目前打开的最大能力增量。
3. **Step 4 清单硬要求「Font CDN `<link>` present」与本机 TLS 重置正面冲突**（fonts.googleapis.com/cdnjs 实测 (35) Connection reset）。本轮改用 `ui-monospace, "SF Mono", Menlo, Consolas` 系统栈、A8 断言反过来查「零 http(s) 引用」——牺牲它一条检查项换单文件可离线。terminal 预设本就是等宽观感，无质量损失。
4. **`getComputedStyle(el,'::after').content` 不解析 `counter()`**：Chrome 返回字面量 `"counter(num)"` → 第 1 版探针 48 帧全 NaN、C1-C3 全 FAIL。计数器要用 `getComputedStyle(el).getPropertyValue('--num')`（注册属性给插值后的整数值）或 `counterReset`（`"num 6"`）双读；本轮 C4 就是拿这两个 API 互相核对。
5. **ffmpeg 的 GIF 编码器写差分子矩形帧，不是逐帧全画布**：48 个 image descriptor 里只有帧 0 是 `0,0,800,800`，其余是 1×1 或局部矩形（本轮 13 种）。第 1 版 B5「每帧描述符都是 800×800」因此假 FAIL。正确不变量：帧 0 全画布 + 所有矩形落在画布内（47KB 装下 48 帧 800×800 正是靠这个差分）。
6. **帧延迟不恒定**：100/12 = 8.33 厘秒 → ffmpeg 在 8 与 9 之间交替。断言要写成 `set ⊂ {8,9} && |mean-8.33|<0.2`，写 `=== 8` 会假 FAIL。
7. **D2 第一次假 FAIL 是我自己的键粒度错**：把 cursor opacity 按 `>0.5` 二值化当状态键，于是 opacity=0.98 与 1.0 被判为同态却像素不同 → 误报 4 组"不确定性"。改用全精度状态键后 48 帧 → 22 个状态、0 组背离，才得出"寻址位级可复现"的真结论。教训与前两轮同源：**FAIL 先怀疑预设，再怀疑产物**。
8. `optimization=balanced` 的第 4 步 gifsicle 本机没有（`which gifsicle` 空）→ 按它自己的「if available」跳过；47KB 已在它给的 email<500KB 门槛内。
9. zsh 的 `$PIPESTATUS` 是空的（zsh 用 `$pipestatus[1]`），日志里那行 `capture rc=` 因此空值；另外误写 `> /tmp_cap.log`（根目录只读）会整条命令挂掉 → 重定向一律用相对路径。
10. `search_extensions` 的参数名是 `query`（`keyword` 会被 schema 拒：`params must NOT have additional properties`）；带连字符的完整 canonicalName 精确检索只回 1 条，比宽词更省。
11. AI 路线（Option B）不是"可选项"而是**死路**：KLING key + 上传本地图 → 双触闸门，但它自带降级条款，照做即可。
