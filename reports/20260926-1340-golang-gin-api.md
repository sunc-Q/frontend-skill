一句话：**它把 Gin 新手最容易漏的生产细节一次性给了齐**——`gin.New()` 而非 `gin.Default()`、`SetTrustedProxies`（否则 `c.ClientIP()` 可伪造）、`ReadHeaderTimeout` 防 Slowloris(CWE-400)、`ShouldBind*` 而非 `Bind*`、AppError 把状态码留在域层、panic 时栈只进服务端日志、`c.Copy()` 才能进协程。本轮 19 条断言全绿即是这套规范可直接照抄的证据。

## 踩到的坑（3 条真报错）

1. **技能文档里的 `c.ShouldBindURI` 在 Gin 里不存在**，真实方法是 `ShouldBindUri`（小写 r）。SKILL.md 与 references/error-handling.md 两处都写错，首次编译直接失败：
   `internal/handler/user_handler.go:50:14: c.ShouldBindURI undefined (type *gin.Context has no field or method ShouldBindURI, but does have method ShouldBindUri)`
   → 抄它代码时要改成 `ShouldBindUri`。（同类：`http.StatusServerTimeout` 也不存在，本轮改用 503 `StatusServiceUnavailable`。）
2. **断言两次被 Go 的输出编码坑**：
   - `encoding/json` 把 `&` `<` `>` 转义成 `\u0026`，所以消毒后的 `<b>` → 线上传输是 `\u0026lt;b\u0026gt;`，直接 grep `&lt;b&gt;` 判失败——必须先 JSON 解码再比字符串（A4 改成用 `node` 解析 `.name`）。
   - `net/http` 会规范化响应头大小写：技能设的 `X-Request-ID` 实际回的是 `X-Request-Id`，断言得 `-i` 忽略大小写（A15）。
3. **`go build -o ../../.tmp/api` 的相对路径按「当前目录」解析**，而 `cd src` 后 `../..` 已是 `demos/`，产物写去了 `demos/.tmp/`，于是后面两轮跑的都是**旧二进制**（表现为「改了代码断言还红」的假故障）。教训：Go 产物一律用字面绝对路径 `-o $LAB/.tmp/...`，别用 `$PWD/../..` 拼（`$PWD` 在子 shell 里已含 `src`）。另外 `GOMODCACHE` 必须是绝对路径，`go` 直接拒绝相对值。

## 顺手发现并修掉的真缺陷

首轮全绿转录里 `"page":0`——handler 直接把绑定结果回显，而默认值只在 service 内部补，于是**响应回显了未填充的零值**（技能示例代码本身就是这个形状）。修法：绑定后、调用前在 handler 归一化 `page/limit`，并加断言 A19（`GET /users` 不带参数必须回显 `page=1 limit=20`）。
