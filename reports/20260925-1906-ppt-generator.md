## 6. 验证结果

**A. 技能自带 checker**：5/5 `[OK] Fully passed`（校验 viewBox 1280×720、禁 foreignObject/clipPath/mask/class/`<style>`、禁 rgba、禁 animate/script/marker、组透明度等 §X 约束）。

**B. 我对 .pptx 的独立断言 13/13 PASS**（关键几条）：
- `sp=211 pic=0` 且 `ppt/media/` 为空 → **确实是原生形状**，不是把 SVG 渲染成位图贴上去（这正是 SKILL.md 警告的 `use_native_shapes=True` 开关的作用）。
- python-pptx 能 `Presentation()` 打开；slide 尺寸 `12192000×6858000 EMU` = 标准 16:9。
- 文本可读回：`只有生成艺术那一轮超时`、`四种产物，四条不同的发现`、`420/600/1140/780`、`5 / 5` 全在 `<a:t>` 里 → 中文没丢、没变图片。
- 无 `{{PLACEHOLDER}}` 残留。
- 柱状图 4 根柱体作为独立 shape，实测高度 `[115.3, 137.9, 300.0, 205.3]`px **与秒数成正比**（比例尺 300px/1140s）→ 数据可视化没画错。
- `val="39FF14"` 在 slide1 XML 出现 25 次 → 霓虹色板进了 srgbClr。

**C. 浏览器真实渲染（getBBox）**：`/3` 柱高属性值与 PPTX 内 shape 高度逐一致；标题 bbox `x=59 y=40 w=455 h=45`；`/4` 最密页 texts=37、超出画布 0 条。

## 7. 踩的坑

1. **技能的 Interaction Flow 与无人值守冲突**：SKILL.md 的 Step 1–4 强制「先问时长 → 再选样式 → 再确认大纲 → 用户说了才生成」，还写死「Duration is required — do not skip」。本任务不许问人 → 只能自答五步（时长取 10 min → 5 页精简，样式取 pixel_retro）。留用时若给人用要提醒这点。
2. **`from svg_to_pptx import ...` 的 sys.path 是别人的机器**：SKILL.md 里写死 `~/.openclaw/workspace/skills/ppt-generator/...`，本机路径是 `~/.qoder-cn/skills/...`。不改成 `expanduser` + 实际路径直接 ImportError。
3. **Python 3.14 环境下 pip 只有一条活路**：`pip3` shim 因 sandbox 里没有 `realpath` 而自毁（`python3.14: No such file or directory`），必须 `python3 -m pip`；镜像用清华源（`curl -o /dev/null -w %{http_code}` 实测 200，本机唯一可达的 PyPI 镜像，跟 npm 走 npmmirror 同理）。lxml/Pillow 有 cp314 wheel，6 秒装完 —— 前几轮「python 路线一律不可用」的假设**过宽了**，本实验室第一次跑通 python 依赖。
4. **技能自己的 checker 不查它自己定的边距**：design_spec §II 写了「左右边距 60px / 安全区 x:60–1220」，但 `/4` 里 `repeat(6,1fr) 被 min-content 顶住 → 须 minmax(0,1fr)` 那行实测右端 **1248px**，超安全区 28px，而 `svg_quality_checker.py` 当时照样给 `[OK]`。→ 边距只能靠 getBBox 自己量；已改短该行并降字号到 15，复测 `beyond-safe-right=0`。这与前两轮「规范指得到、实现层不在包里」是同一类缺陷，但更糟：**它给了一个绿色的假通过**。
5. **两个假失败是我自己的预设错**（记下来给后续轮次省事）：(a) 按「宽 130px」筛柱体命中 8 个——柱体与它 10px 高的顶部高光条同宽，要再加 `height>50px`；(b) 转换器打印 `Speaker notes: Enabled (no notes files found)`，实际仍逐页写出 5 个**空** `notesSlideN.xml`（无害，但与日志不符，断言别写成「无 notesSlide」）。
6. `window.innerWidth` 在 IDE 面板仍是 0，但 SVG 用户坐标与 getBBox 不受影响 → 矢量产物比位图产物更适合本环境的验证（前几轮的像素直方图那套在本轮不需要）。

## 8. 效果结论：留用

**留用**。理由：这是本实验室第一个**真·二进制办公文档**产物，而且「可编辑」不是嘴上说的——`pic=0 / sp=211 / 中文在 `<a:t>` 里 / 柱高与数据成正比` 四条独立断言都能验穿。色板与版式规范具体到 hex 与像素级，SVG 约束（禁 class/foreignObject/rgba/marker）是**可机检**的，跑一遍就知道自己有没有守规矩。

代价与边界：完整流程要 3 轮人工确认（不适合无人值守，得自答）；依赖 python-pptx（需 `python3 -m pip --target`）；技能自带 checker 有假通过（边距不查），所以**必须**再叠一层 getBBox + PPTX 结构断言才算验完。

对后续轮次的直接价值：`scripts/` 里还有 `pptx_validator`、`visual_reviewer`、36 张 `templates/charts/*.svg`（雷达/甘特/桑基/热力图…）和 600+ 图标索引没动 —— 想把台账做成「带真图表的多页 deck」时，这个技能是现成的实现层。
