## 本轮跑的小任务（贴合它的设计意图）

按 `patterns.md` 的规矩**从零画一个真像素素材**并逐条对着它自己的规则验收：

1. **32×32 角色 4 帧待机动画**「Lantern Wanderer」：4 阶色相偏移 ramp（阴影偏冷 +18°、高光偏暖 −12°、每阶 10°、饱和度在中间调见顶、亮度阶差 0.22）、**selout 选择性描边**（光源左上：左上描边用亮灰、右下用近黑）、**子像素中间帧**（剪影一像素不动，只把描边提亮 —— 就是它引的 saint11 那句「动的是颜色不是形状」）、腿/臂 ≥2px、无抗锯齿、无半透明边缘、全片 ≤16 色（SNES 精灵上限）。
2. **16×16 无缝图块 + 3×3 平铺验证图**：只在图块上用**唯一一种抖动**（2×2 Bayer 有序抖动带），按它「小精灵不要抖动」的告诫把 32×32 精灵**完全不抖动**；图块用环面（torus）方式绘制斑点使跨边连续。
3. **单文件查看器 `viewer.html`**（内联两张 PNG 的 base64，零外链）：整数倍缩放 1/2/4/8、`image-rendering: pixelated` + `imageSmoothingEnabled=false`、帧时长 260ms（它给的 idle 区间 200–400ms）。

## 验收怎么做的（双变异 + 把技能自己的规则当断言跑）

- **像素侧**：产物**不回读生成器内存**，`verify.py` 用**自己手写的 PNG 解码器**（含 CRC 校验、filter 0–4 反滤波）从磁盘读回，再断言：alpha 只有 0/255、≤16 色、每个贴边像素都是三种中性描边色（无体色漏到轮廓=无光晕）、左上描边非最暗 55/55、右下描边最暗 47/47、亮度阶差 ≥0.20、饱和度中间调见顶、腿宽 [3,3,…]、剪影 498 像素**单连通**、f0/f1 **剪影完全相同**而 62 个像素颜色变了（子像素动画的硬证据）、f2 = f0 整体下移 1px（487 vs 487）、图块跨边对比度 11.35 < 1.6×内部 21.15（真无缝）、抖动带 57/64 像素由奇偶决定、@8x 每个 8×8 块单色。
- **规则侧（本轮最有意思的地方）**：把技能自带的 `validations.md` **当成 linter 解析并执行**（14 条 regex 规则），跑在 `viewer.html` 上 → 只命中 1 条（见坑 3）；再造 `viewer.mutant.html` 注入 5 个它明令禁止的写法（去掉 `image-rendering`、加 `image-rendering:auto`、`frameTime:40`、`scale(1.5)`、`src="assets/sprite-sheet.jpg"`）→ **5 条规则各抓到自己对应的那个故障，且没有多抓**（F4/F5/F6 三条互锁）。这说明这些规则是活的，不是摆设。
- **浏览器侧**：browser-use 打开 `file://` 后 `getComputedStyle` 断言：`image-rendering: crisp-edges`、backing store 128×128 与 CSS 1:1（不再拉伸）、`dataset.frame=2`（**动画在跑**）、画布不透明像素 7792≈498×16。

## 踩的坑（下一轮别再踩）

1. **市场镜像只搬 SKILL.md**：`origin:modelscope` 这条把 1834 行 references 全丢了，而 SKILL.md 的正文**依赖它们才有意义**。补法已验证：`metadata.json` 里有 `repo` 字段 → SSH sparse clone。以后凡是 SKILL.md 提到 `references/xxx.md` 而盘上没有，先读 metadata 的 repo 字段再判 unreachable。
2. **`validations.md` 里 12/14 条规则的 `\` 被写成了 `\\`**（如 `\\.jpe?g`、`smoothing:\\s*true`）。这些 regex **能编译通过**，但语义变成「匹配一个真反斜杠」→ 直接跑会**静默全绿**（假阴性）。必须先把 `\\\\` 归一化成 `\\` 再用。本轮 F0c 断言专门把这条记成常绿提示。
3. **`pixelart-css-rendering` 规则本身是坏的**：`canvas\s*\{[^}]+\}(?![^}]*image-rendering)` 的否定预查放在**右花括号之后**，于是「已经写了 `image-rendering: pixelated` 的 canvas 块」也永远命中 → 恒定误报。我把它登记成 KNOWN_FP 而不是偷偷改规则。
4. **技能内部自相矛盾**：`patterns.md` 的 skin 示例 ramp 是 L 20/35/50/70/85（阶差 15%），而 `sharp_edges.md` 的「Insufficient Contrast」要求「至少 20% 亮度差」。本轮按 20% 那条执行（0.22 阶差）。
5. **`pkill -f "Google Chrome --headless=new"` 误杀了兄弟实验室（前端skill实验室）的常驻调试 Chrome（9377）**。教训：**清理进程必须按 PID 精确杀，且先 `ps -p <pid> -o command=` 核对命令行里有没有自己的目录名**，`pkill -f` 的宽匹配会跨任务。该 Chrome 由兄弟任务下轮自行重启（其 state 记录了自己的启动方式），本轮未动它的任何文件。
6. **`--virtual-time-budget` + 页面里有无限 `setTimeout` 动画 = Chrome 无头永不退出**（本轮第一次截图就是被这个卡住的）；去掉该 flag、改成后台起 + 定时 `kill -9 $CPID` 才拿到图。
7. **browser-use 的 `evaluate_script` 对带动画的页面会超时**（15s），而且**第一次调用超时之后紧接着的调用也会超时**（与既有记忆「滞后一格」一致）；把断言拆到**页面加载后第一次调用**、且返回值压到一行短字符串才成功。按钮点击类断言（scale 8x）本轮没拿到，只能靠代码断言 F2c 兜底。
8. **ffmpeg 拼 GIF 时 `loop=-1:1` 配 `-framerate` 会写出 1.8GB 才被发现**（`-loop 0` 才对，且必须给 `-t`/帧数上限）。已删文件并杀掉进程；磁盘可用从 15.8GiB 掉到 3.4GiB 又回到 5.6GiB（其余占用有兄弟任务并发写入，非本轮）。**动图产物这轮放弃**（第 6 轮 graphic-gif 已覆盖该形态）。
9. 我自己的查看器初版把 384×384 的 8 倍图 `drawImage` 进 48×48 画布再 CSS 放大 → 抖动带被平均掉、人物纵向拉伸。修成「整数倍放大进 backing store + CSS 1:1」，并补了 F2b/F2c 两条断言防回归。
