## 1. 本轮切口为什么新

六轮历史分别打的是：订阅价格阶梯（1）、容量与候补（2）、多目的国税则折算（3）、招生漏斗（4）、
出餐时间流水线（5）、判分口径唯一性（6）。本轮打的是**逐夜价格档的优先级仲裁 + 半开区间排他**：

```
五级优先价（高→低）：房型特价日 > 房型停售 > 整院停售 > 全局节假日倍率 > 周末倍率 > 平日基准
区间口径：[check_in, check_out) 半开，离店日不计夜
民宿特有约束：退房后 clean_buffer_days 清洁缓冲内不可复住；周五/周六夜 min_stay_weekend 最少连住
```

关键结构性保证：**只有一个算价引擎**（`domain.BuildQuote`）。种子灌数走它、线上下单走它、
试算接口走它，统计层（ADR/OCC/RevPAR/价格档分布）只从落库的 `booking_nights` 聚合，
**绝不第二次算价**——这是第 6 轮「判分口径唯一性」教训在定价场景上的复用。

对外实时公布三条恒等式（接口回布尔位，页面右下角有"恒等式体检"卡）：

| 恒等式 | 本轮实测（刚灌完种子的临时实例） |
|---|---|
| `Σ逐夜金额 == 房费小计` | 80,401,100 == 80,401,100 分 ✅ |
| `总额 == 房费小计 + 清洁费` | 逐单成立（清洁费合计 3,343,000 分）✅ |
| `实收 == 成交额 + 取消单总额 − 退款` | 837,441.00 + 107,546.00 − 47,549.20 = 897,437.80 ✅ |
| `RevPAR ≈ ADR × OCC` | 310.01 vs 推导 309.91，漂移 10 分（整除误差）✅ |

## 5. 本轮抓到的问题（都已修）

1. **API 列表键名不统一**：`/api/properties` 回 `properties` 而其它列表回 `items`，前端按 `items` 读 →
   顶部「0 家门店」、门店筛选、门店组合卡全空，**而所有接口状态码都是 200、go test 全绿**。
   修：键名统一 `items`；冒烟加 `pick_room`（取不到 `items[0].code` 就 die），把"键名与条数"纳入断言。
2. **`/health` 的 time 是 UTC，业务 today 是本地**（2026-09-25T16:50Z vs 2026-09-26），
   冒烟从 health 取 today 会让全部日期断言偏一天 → 统一从 `/stats?days=1` 取。
3. **种子房型名混进英文残片** `layered 台地房` → 改「层台地景房」。接口断言看不见，**截图才看得见**。
4. **模板 CSS 的固定栏数撑破新页面**三处：`.form-row` 5 栏网格把两个日期框挤到溢出、
   `.kpi-*` 是 `<span>` 导致 52px 大数字压住说明文字、`.cal-name` 定宽 168px 溢到相邻格子下。
   全部修在 `derive-themes.py` 的 `SHARED` 段（三风格共用一条规则），**不改 DOM**。
5. **`file://` 打开单文件预览拿不到数据是故意的**：`Origin: null` 不被 CORS 放行
   （放行等于对所有本地程序开门），预览版走 `serve-static.mjs` 的同机 http。README §6 坑 5 已写明。
6. **favicon 404 被记成页面错误** → `index.html` 加 `<link rel="icon" href="data:,">`（`data:` 不算外链）。
7. **风格改名避嫌**：初稿「等距工业蓝图」与第 6 轮已用「蓝图工程制图」相邻 → 改「等距轴测工业风」，
   并清掉 CSS 注释里残留的「蓝图纸」字样。

- 「单一引擎 + 对外公布恒等式」这条第 6 轮学到的结构纪律，在定价场景同样有效：
  种子自检测试能直接对 472 间夜断言金额恒等、零超卖、缓冲/停售合规，比任何截图可靠。

  下单无幂等键；stats 只有固定两档窗口。
