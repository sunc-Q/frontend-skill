## 它自称干什么

创建 / 编辑 / 读 Word 文档，含目录、页码、表格、图片、批注（comments）、修订追踪（redlining）、`.doc` 转换。三条路线：新建走 `docx`(npm)；改已有走 `unzip → 编辑 document.xml → zip`；读走 `pandoc -t markdown`。自带 4 个可执行脚本：`office/validate.py`（XSD + 修订完整性校验）、`comment.py`（一次写入 6 个互链部件）、`merge_runs.py`（合并被 Word 打散的 run）、`accept_changes.py`。

## 本轮跑的小任务（贴合它的设计意图）

不是做网页，而是做**它最独有的三件事同时来一遍**：一份可交付的 Word 评审纪要，带真目录域、真页码域、双宽度表格、内嵌图片、点前导行，再用它自己的 `comment.py` 打 3 条批注（其中 1 条是回复线程），最后按它「Editing existing documents」章节手工写 `<w:ins>/<w:del>` 做两处修订。内容就是本流水线自己前 11 轮的台账（`facts.cjs` 现场从 `state.json` + 各轮 `output.log` 实测，不写死）。

## 踩的坑（下轮直接抄）

1. **★docx-js 的 `TextRun({text, children})` 会静默丢掉 `text`。** 按 SKILL.md 第 33 行做点前导（dot leader）时我写成「一个 run 同时给 text 和 PositionalTab children」，结果 5 个 KPI 标签文字（"已验证技能数" 等）**整批从正文蒸发**，而 `validate.py` 照样 "All validations PASSED!"。修法：把 `PositionalTab` 单独放一个不带 text 的 run。这是第 5 轮「技能自带 checker 会给假通过」的又一次命中，且这次丢的是**内容**不是样式——凡生成型产物，必须有一条「期望文字确实在文档里」的断言（本轮为 D1「11 个 skill 名全部存活」+ verify 里的标签计数）。A/B 证据留在 `ab_docxjs_textdrop.txt`。
2. **docx-js 不写 `Normal` / `DefaultParagraphFont`，却让自家样式 basedOn 它们；`comment.py` 的标记 run 又引用谁都没定义的 `CommentReference`。** 结果：样式表里 3 处悬空引用，python-docx 对 17 个无 pStyle 的段落返回 `paragraph.style is None`，`validate.py` 全绿（它只做 XSD 语法校验，不解析样式引用）。已补 `fix_styles.py` 注入 5 个样式定义，G1–G5 五条断言前后对照。教训：**「样式引用悬空」和「公式假 0」是同一类缺陷——语法合法、语义静默降级，只有第二个解析器会暴露**。
3. **修订 id 必须全局唯一，而 `--author` 校验不查它。** 我第一版在两个段落各写一对 `<w:ins>/<w:del>` 都用了硬编码 9001/9002，validator 依旧 PASS，是我自己的 B5 断言（id 去重）先红。改成 `itertools.count()` 后 4 个 id 各不同。
4. **单行 XML 上的正则会跨 run 吞掉前一个 run。** `<w:r>(<w:rPr>.*?</w:rPr>)<w:t>目标</w:t></w:r>` 在 document.xml 只有一行时，`.*?` 会从**上一个** run 的 `<w:rPr>` 起匹配，把上一句 `<w:t>` 整体搬进 `<w:del>` 里——正是 validator 报的「`<w:t>` found within `<w:del>`」。正确写法是 tempered 模式：`<w:rPr>(?:(?!</w:rPr>).)*?</w:rPr>`。这条我故意留在 `run.sh` 第 5 步做 A/B 对照，好让「checker 有牙」本身也被验证一次。
5. **它强制的「渲染出来亲眼看」在本机是死路**：`which soffice` / `pdftoppm` / `pandoc` 三个全 MISSING（第 9 轮已记 LibreOffice 缺失，本轮补上 pandoc 与 poppler 同样缺失）。替代三件套已跑通并可复用：`preview.py`（按 document.xml 顺序导出 ~删除线~ / ⟦插入⟧ / 〔批注〕）+ `verify.py`（OOXML 断言）+ `readback.py`（python-docx 回读）。
6. **系统 Chrome 无头 CLI 能直接出图，不需要 playwright**：`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=2500 --window-size=720,320 --screenshot=chart.png --default-background-color=FFFFFFFF file://…/chart.html` → 33,756B 真 720×320 PNG，中文标签正常。比第 6/11 轮的 playwright 路线省掉 13–140MB 依赖，适合只需要一张图的场合。
7. **python-docx 的 `.text` 不含 `<w:ins>`/`<w:del>` 里的文字**（第 7c 步实测：三段修订文字 "in .text: False | in document XML: True"），也拿不到表格段落。用第三方解析器写探针时，**先确认它看不到是文件的问题还是 API 的口径**，否则会误判产物坏了。
8. `set -euo pipefail` 与「故意跑一个已知会失败的 A/B 对照」冲突：`-e` 会在第 5 步直接终止。无人值守流水线里要跑负样本时，去掉 `-e` 改成显式记 `exit=$?`。
9. 沙箱里 `require.resolve('docx')` 全局不存在（SKILL.md 说 "docx is preinstalled" 是它母环境的假设），必须 `npm install`；`node -e "require('docx/package.json')"` 会被 exports 字段拒绝，取版本请读 `node_modules/docx/package.json`。
