## 本轮跑的小任务
给它一个贴合设计意图的活：**把本实验室自己的运行台账 `state/state.json` 包成一个只读 MCP 服务器**
（`skill-showcase-ledger-mcp-server`），4 个工具：
`ledger_get_summary` / `ledger_list_runs`（limit 1-100 + offset + markdown|json）/
`ledger_get_run`（按 skill 名子串查详情）/ `ledger_search_skills`（在 verdict/source 上做全文检索 + `kept_only`）。
每个工具都按 guide 要求带 `title` / 显式 `description`（含 Use when / Don't use when 路由）/
Zod `inputSchema` / `outputSchema` / 四个 annotations / `structuredContent`，并实现
`CHARACTER_LIMIT=25000` 截断 + 可执行错误消息。
然后按它 Phase 4 产出 `evaluation.xml`（10 道只读、可字符串核对的题），并用真 MCP 会话把 10 题**逐题只用工具解出来**。

## 验证（不是声称，是跑出来的）
- 握手：`serverInfo.name=skill-showcase-ledger-mcp-server`，`capabilities={"tools":{"listChanged":true}}`
- 契约：4/4 工具 snake_case 且带 `ledger_` 前缀；4/4 有 `outputSchema`（10/8/8/7 字段）；
  4/4 四个 annotation 全为布尔且 `readOnlyHint=true, destructiveHint=false`
- 数据：`ledger_get_summary` 的 8 个字段与 Python 侧独立重算逐字段 `JSON.stringify` 相等
  （runs_total 15 / skills_kept 15 / total_seconds 12660 / average 904.3 / slowest canvas-design）
- 分页：offset 0 与 3 两个窗口**技能名零交集**且 index 连续
- 截断：真实台账 4,268B 远不到 25,000 → 断言**不该**截断；另造 300 条 fat ledger → 真截断到 50/300、
  文本 19,969B ≤ 上限、`truncation_message` 点名 offset/limit
- 错误：未知 skill 名 → `isError:true` 且消息含候选名 + 下一步该调哪个工具；`limit=999` 在进 handler 前被 Zod 挡下
- 幂等：同一调用两次 `structuredContent` 逐字节相同（兑现它自己声明的 `idempotentHint:true`）
- 评测：10/10 答案**只靠 MCP 工具**解出并与 Python 独立算出的答案一致
- 变异（负对照）：删 annotations→只红 B5；分页忽略 offset→只红 D1；空结果不给 structuredContent→只红 D8

## 效果结论：**留用（推荐）**
理由：它是这个实验室第一个「产物=协议能力」的技能，交付的不是一个文件而是一个能被任意 MCP 客户端
挂载的服务；它的 reference 密度极高（969 行 TS 指南）且几乎每条建议都能落成断言；
更重要的是它教的 `outputSchema` 是**有牙的契约**，逼出了一条只有真起会话才看得见、
前 15 轮（file:// / 像素 / 静态审读 / 文档解析）都覆盖不到的缺陷类型。

## 踩的坑（下轮直接抄）
1. **★声明了 `outputSchema` 就每一条返回路径都必须带 `structuredContent`。** 我第一次真机跑线，
   `ledger_search_skills` 的空结果分支只 return 了 `content`（想给一句友好提示），SDK 立刻把它判成
   `-32602 Output validation error: Tool … has an output schema but no structured content was provided`
   ——友好提示根本没送到调用方手里，整个工具调用变成错误。修法：空结果也返回
   `{total:0,count:0,matches:[]}`。同理 `isError` 分支可豁免（SDK 对 `isError:true` 不校验输出，实测 D6 通过）。
   **这条只有在 stdio 上真起会话才会暴露**，写代码时完全看不出来。
2. **Phase 4.3 的 “Stable: answer won't change over time” 与 append-only 台账正面冲突**：任何「一共跑了多少轮」
   这类题，在我把本轮记录写回 state.json 的那一刻答案就变了（15→16）。所以 10 道题全部改成锚定不可变事实
   （首条记录、指定 skill 的历史记录、列表头部窗口）。第一版我出的 Q1 答案写成 `"drafter 2026-09-25T17:23+08:00"`
   这种跨字段拼接串，工具结果 JSON 里**根本没有这个连续字符串**，F1 直接红——回到它自己的要求：
   *单一、可字符串比对核验的答案*，一题一字段。
3. **SKILL.md 的强制联网步骤在本机全不可用**：Phase 1.2/1.3 要求 WebFetch
   `modelcontextprotocol.io/sitemap.xml` 与 `raw.githubusercontent.com/.../typescript-sdk/README.md`
   （本机 HTTPS 被 TLS 重置）。好在 `reference/node_mcp_server.md`（969 行）本地就有，覆盖到能替代它；
   按本地 reference 落地即可，别去探测那两个域名。
4. **Phase 3 的 `npx @modelcontextprotocol/inspector` 与 Phase 4 的 `scripts/evaluation.py` 都用不了**：
   npx 会打不可达源；`evaluation.py`/`connections.py` 的 `requirements.txt` 是 `anthropic>=0.39.0 mcp>=1.1.0`，
   跑 LLM 评测回路需要 **ANTHROPIC_API_KEY（付费凭据）**→ 按闸门要求立刻放弃该子步骤，只交付
   Phase 4.4 的 `evaluation.xml`，并把「解答题目」这件事用 MCP SDK 自带的 `Client + StdioClientTransport`
   自己写成脚本 —— 结果比 Inspector 更适合无人值守（692ms 跑完 32 条断言，可退出码判定）。
5. **Truncation 分支在真实小数据上是死代码**：`CHARACTER_LIMIT=25000` 对 15 条记录（4,268B）永不触发，
   「照着技能写截断」等于没测。必须另造一个 fat ledger（300 条 × 长 notes）才能证伪。顺带：技能原文
   `data.slice(0, data.length/2)` 一次减半，我实测从 100 条一次减到 50 条刚好过线，但**若单条 notes 极长，
   减半仍可能超限** —— 它的示例里没有 while 收敛环，我补了一个（`fit()`），否则 D3 会不稳。
6. **语言选择偏离 guide（自知代价）**：guide 明确推荐 TypeScript + `npm run build` + `z.infer<>` 类型层。
   本轮守 15 分钟预算，用 ESM JavaScript 写（`registerTool` / Zod shape / annotations / structuredContent
   全部照抄），代价是丢掉静态类型与 build 这一步；补偿是 verify.mjs 里把 schema 完整性做成运行期断言（B3/B4）。
   下轮若要产出可交付的 MCP 包，应回到 TS + tsup 并跑 `npm run build`。
7. **wire 层与文档的小差异**：guide 示例把返回 JSON 形状**写在 description 文本里**（人读的），
   而 `outputSchema` 才是机读的；`tools/list` 返回的 `inputSchema` 在 SDK 1.30.1 下**只带 properties，
   不带 required 数组**（因为有 `.default()` 的字段被视作可选），别断言 required。
   另外 SDK 版本号我一开始写成 `^4.4.3` 的 zod 实际装的是 4.6.5 —— 落 package.json 前要 `node -e require(...version)` 核对。
8. **子目录运行会打破相对路径**：变异体放在 `.mut/` 里时，服务器默认的
   `new URL("../../../state/state.json", import.meta.url)` 少算一层 → 直接 `ENOENT …/demos/state/state.json`
   且表现为「Connection closed」这种极难定位的客户端错误。已改成显式 `LEDGER_STATE_PATH` 注入
   （中文目录必须 `fileURLToPath`，否则 `import.meta.url` 是 `%E8%AF%95%E9%AA%8C` 转义串）。

## 环境事实新增
- **MCP 开发路线在本机完全可用**：`@modelcontextprotocol/sdk` 1.30.1 + `zod` 4.6.5，npmmirror 装 94 包 / 4s，
  纯 JS 无原生依赖、无浏览器；一整套「起服务 → 客户端 → 断言」用 `node` 两条命令即可，全在 LAB 内。
