**六条泳道里有两条（33%）会被这条公式画成「一格不差」**，而它们恰好都是「还差一件事就收工」的状态 —— 这正是看板最不该骗人的地方。这不是构造出来的边界值：`Math.round(9.5)=10`、`Math.round(9.6)=10`，也就是说 **95%~99% 整段区间全部塌到满格**，而 95~99% 恰恰是「只差最后一项」的常见落点（19/20、20/21、22/23、45/46、…，分母越大越密）。

修复（`src/render.mjs:102`）：满格只允许真·全完成，其余钳到 9/10 ——

```js
export function filledBlocks(pct, done, total) {
  const naive = Math.round(pct / 10);
  return done === total ? 10 : Math.min(9, naive);
}
export function eighths(pct, done, total) {          // dense 八分度同口径
  const naive = Math.round((pct / 100) * 80);
  return done === total ? 80 : Math.min(79, naive);
}
```

我一度另写过一行 `wouldOverclaim = (pct, done, total) => Math.round(pct / 10) === 10 && done !== total` 想在产物里附一句「哪些格原本会谎报」的披露，实测发现没有任何断言真正依赖它、而 A4 臂已经从公式独立反推越界，于是**删掉了这个死导出**（上一版报告把它当作现存代码抄在这里，属于手抄失真）。

dense 风格的 79/80 钳位同理（八分度条在 98.75% 以上仍会进位成满条）。这条纠偏由三支断言从三个方向钉住：`A3x-<风格>`（产物里凡满格条，其泳道必须真·全完成）、`A4-<风格>`（**技能原公式在本轮数据上确实会过度声明** —— 断言的是缺陷存在性，所以将来若有人偷偷改回原公式、或数据变了，都会当场报红），以及变异臂 `M5a/M5b/M5c`（构造 `199/200` 这一非本轮数据的边界：钳位后不得画满、原公式在 199/200 上确实画满、dense 的 79/80 同测）。M5b 的意义是**证明这不是给本轮数据打的补丁**，而是一条与数据无关的公式性质。

看板上的呈现因此是自证的：CLEAN 与 DEDUP 两行画 9 格、百分比仍写 96%/95%，差额看得见。

## 5. 发现二：十格量化的死区 —— 54% 和 46% 画出同一个条

同一条公式的另一半问题：`round(pct/10)` 的分辨率是 10 格，落在同一个格内的百分比**画不出差别**。本轮活例：自检 HEALTH 7/13 = 53.85% → pct=54 → 5 格；6/13 = 46.15% → pct=46 → **同样 5 格**。也就是说这条泳道少做一项（7→6），看板上的条**一动不动**。

断言 M1e 把这个死区固定成可回归的读数：它先由 M1a 确认「改坏一项后 pct 确实从 54 掉到 46」，再断言 **matrix 的条一字未动**，落盘读数就是 `54% 与 46% 都画成 ▓▓▓▓▓░░░░░`；同一条变异打到 dense 的八分度条上是 `█████▍▒▒▒▒`(43/80) → `████▋▒▒▒▒▒`(37/80)，M1b 断言的正是「十格吞掉的差异必须在八分度上可见」，并附加两格都仍为 10 列（`cells()==10`）不变形。死区没有「修掉」—— 十格是技能的原生主张（SKILL.md:60 `Always 10 characters`），把它细化是另一种风格的责任，所以两种条并置本身就是这条问题的答案。

**结论：技能的十格条适合「汇报口径」，不适合「逐日盯口径」；后者要用 dense 的八分度。** 这是本轮三风格并置真正量出来的东西：同一条 54% 的泳道，matrix 画 `▓▓▓▓▓░░░░░`、dense 画 `█████▍▒▒▒▒`（43/80），只有后者在少做一项时会动。

## 6. 发现三（本轮最贵）：`monospace (10 chars = 10 chars)` 这个前提在浏览器里为假，且**本机没有任何字体能满足它**

SKILL.md:179 假设「等宽字体：10 个字符 = 10 个字符宽」。用本机 Chrome 无头（`--headless=new --dump-dom`）在 `font-family:monospace; font-size:12.5px` 下逐字符量步进（`check-browser.mjs` 的探针实测，读数落 `.tmp-check/browser-meta.json`）：

| 字符类 | 探针 | 实测 px | ÷ mono(7.526px) = 格数 | `cells()` 口径 | 偏差 |
| --- | --- | --- | --- | --- | --- |
| ASCII/盒线/块字符 `▓░─█#.` | 各 | 7.526 | **1.000** | 1 | ✅ 前提成立 |
| CJK「项」 | U+9879 | 12.500 | **1.661** | 2 | ❌ 差 0.339 格 |
| emoji ✅ | U+2705 | 16.000 | **2.126** | 2 | ❌ 差 0.126 格 |
| 盲文 ⣿ | U+28BF | 8.545 | **1.135** | 1 | ❌ 差 0.135 格 |

`mono=7.526px` 而 CJK 回退字体步进恰为 **1 个 em（12.5px）** —— 即 **CJK : ASCII = 1.661 : 1，不是 2 : 1**。这条不是「换个字体就好」的配置问题，本轮把它量成了证据（`BB11`）：用同一套探针在 14 个字族下各测一遍 ASCII 与 CJK 步进，比值为

```
monospace=1.661  Menlo=1.661  Monaco=1.666  Courier New=1.666  ← 真·等宽拉丁，CJK 全部回退到 1em
SFMono-Regular=1.134  PingFang SC=1.134  Heiti SC=1.088  Songti SC=1.201  STSong=1.201  Kaiti SC=1.134
Noto Sans Mono CJK SC=1.134  Source Han Mono SC=1.134  Sarasa Mono SC=1.134  Microsoft YaHei Mono=1.134
```

**14 个候选里最高 1.666，没有一个接近 2**；三款号称「CJK 等宽」的字族（Noto Sans Mono CJK / Source Han Mono / Sarasa Mono）测出与默认回退相同的 1.134，说明本机根本没有解析到它们。**BB11a 是这条断言的自检**：它要求这 14 组的 ASCII 步进不能全同 —— 第一版探针把字族名误传成了 class 参数（`adv(ch, cls, n, fam)` 的第 2 位），14 组数字全部一模一样、断言却照样绿，是 BB11a 逼出来的假测量。修好后才有资格说「换字体没用」。

结论：**技能的等宽前提只在它的条字母表（▓░─█#）上成立；看板里一旦出现中文项目名、emoji 状态图标或盲文曲线，同一份 .md 在浏览器里就会散架。**

实测散架幅度（BB5，把校正脚本剥掉与保留各量一次，比较「同一列上的关键字符」的水平位置离散度）：

- matrix：同列关键字符（17 个 `|+├┤┌┐└┘╔╗╚╝…` 跨 2 个对齐组）**未校正时离散 68.88px，校正后 0.08px**
- dense：**未校正 25.5px → 校正 0.03px**
- teletype：0px —— 它 7-bit 纯 ASCII，根本不需要校正（`hasScript=false`）

修复方式（关键是**不新增第二个宽度模型**）：`src/render.mjs` 里唯一的宽度口径仍是 `cells()`（CJK/emoji/全角=2、零宽=0、其余=1）；HTML 预览层按 `charClass()` 把连续同类宽字符包成 `<span class="fx-cjk|fx-emoji|fx-braille|fx-shape">`，页内内联脚本用与探针完全相同的手法量出该类的实际步进，再把 `letter-spacing = 目标格数 × monoPx − 实测步进` 写进 CSS 变量。目标值来自 `WIDE_FIX = {cjk:2, emoji:2, braille:1, shape:1}`，而 **B11d 断言 `WIDE_FIX[类] === cells(探针字符)`** —— 目标表若与 `cells()` 打架，检查器当场报错。变异臂 M11a/b/c 故意把 `cjk` 目标改成 1、注入未知类，三次都被抓（M10 五臂同理：删脚本 / 把 CJK span 错标成 emoji / 让 span 吞掉一个条字符 / 拆掉 CJK span / 往纯 ASCII 的 teletype 里塞脚本，全部必须被抓到，M10a 是正对照）。

两条诚实边界，都写进了产物：
1. **BB6 断言校正对条形是惰性的**：8 格条的像素宽度在「带校正」与「不带校正」两份拷贝里都必须 == `8 × monoPx`（实测 matrix/dense/teletype 三份都 60.2px）—— 校正只补宽字符，绝不把本来就对的条弄歪。
2. **关掉 JS 会退化**：`preview/styles.html` 页脚如实披露「本预览依赖一段内联脚本做宽字符步进校正，禁用 JS 时中文列会错位；.md 原生载体（GitHub/终端）不受影响」。

## 7. 发现四：看板的 ASCII 区必须围栏，否则任何 Markdown 渲染器都会把它抹平

三张 .md 是**交付物本身**（技能主张「ASCII 看板可直接贴在文档里」），但正文里的 ASCII 区若裸着写，Markdown 会把连续行合并成一段、把 `#` 当标题、把 `|` 表格外抛 —— 本轮把 header/泳道/Sprint 框/时间线统一包进 ``` 围栏。守这条的是三支断言：`B14`（版式区每一条非表格的 art 行都落在某个 ``` 围栏内）、`A12`（Markdown 表格不参与像素对齐，即「表格列宽」与「版式区列宽」是两套口径、不得互相污染）、`B5`（无 tab / 无 CR / 无行尾空格，复制进别处不变形）+ `B6`（.md 零外链，围栏里不塞图片）。这条不是技能原文，是技能原文没写但产物形态必需的（同类先例：12:00 轮的「Suspense 边界挂在哪一层」）。

## 13. 踩坑与工具环境注记（进 `environment_notes`）

1. **Chrome 的 `--user-data-dir` 不能放在本仓库路径下**：仓库根含中文（`试验/前端skill实验室`），Unix socket 路径上限约 104 字节，Chrome 报 `Failed to create ... socket`；profile 目录改放 `os.tmpdir()` 并以 PID 命名、退出即删。
2. **`--dump-dom` 的收尾时机**：不能等 `close`（Chrome 无头进程会在虚拟时间用尽后滞留），改为在 stdout 见到 `</html>` 即 `kill('SIGKILL')`，整体 45s 上限。
3. **断言「同一列上的字符水平位置必须重合」要有正确的列参照**：第一版拿 `cells(md.slice(0, 全局字符偏移))` 算列位置，把换行符也计成列，量出 4,545px 的荒唐残差；正确做法是让 `critTargets()` 在扫描围栏区时**随行携带行内列号**，参照系必须是行内偏移。
4. **探针页里的偏移单位混淆**：`xAt(board, o - x0)` 一度把像素当字符偏移传入，`#probe-out` 静默为空。给探针脚本套 try/catch 并把异常写进 `#probe-out` 是本轮唯一让这条暴露出来的手段 —— 无头浏览器「什么都没输出」不是通过，是没有断言。
5. **宽度分类的边界写错会自我掩盖**：`charClass('▓')` 因块字符区间写成 U+2588–U+259F 而落到 `'other'`，导致「条形族绝不能进校正类」的断言 B11d 当场失败 —— **自己新加的判据抓到了自己新写的 bug**，这是它存在的意义。修正为 U+2580–U+259F，并把 ⬜ 归入 `shape`（目标 1 格）使 `WIDE_FIX` 与 `cells()` 恒等。
6. **围栏改动会打断旧的「第一围栏」假设**：ASCII 区包进 ``` 之后，A6/A6b/M8b 三条「取第一个围栏」的断言立刻错位；改为**按字符集特征挑围栏**（里程碑 `●○` / 条形族），并新增 B14 把「条形行必须在围栏内」升格为受断言的不变式，防止下次再被同一个改动打回。
7. **清理类断言必须跟着产物形态一起改**：CL6「HTML 自包含」原把内联 `<script>` 一律判死，BB 系列引入校正脚本后误报；改为「允许内联脚本但要求脚本体纯 ASCII、且零外部 `src`/`href`/`url()`/`@import`」。CL9 同理放行 `.tmp-check/probe-*.html` 六份探针拷贝，并加 CL9b 断言探针绝不外泄进交付目录。
8. **`sh` 里 `cd "$(dirname "$0")/../../.."`**：`verify.sh` 在 `artifacts/<轮>/scripts/` 下，仓库根差三层；少写一层就变成 MODULE_NOT_FOUND（本轮踩过一次，且报错信息只说找不到模块、不说找错目录）。
9. **恒等式在退化输入上会自我证明**：teletype 是纯 ASCII，`spans=0`、`hasScript=false`，所以「span 数 == 宽字符段数」这类断言在它上面是空转的 —— 本轮为此专门加正对照 M10a，并让 matrix/dense 两臂承担全部强度，避免「三风格全绿」里其实只有两风格在测。
10. **测量装置自己也要有对照**：字族扫描的第一版把家族名传给了 `mk(cls, fam)` 的 class 位（`adv(ch, cls, n, fam)` 的第 2 个参数），14 个字族全测出同一个步进 —— 数字漂亮、断言照绿，**这是一次典型的「装置静默失效」**。补了 BB11a（要求各字族的 ASCII 步进至少出现 3 个不同值）之后，这类「参数错位导致的假测量」才当场露馅。凡「换一批输入却读数完全相同」的扫描，都该配一条这种灵敏度判据。
11. **本产物目录形态从简**：本轮零 `node_modules`、零 `dist`、零构建日志。产物目录磁盘 651KB / 入库 486KB（**故意取整到 KB**：台账文本本身会进 facts.json，字节精确值会随每次重跑抖几十 B，写死就是给自己埋假红），拆开是交付物 276KB（三份 .md + 四份 HTML + `src/` + `scripts/` + `facts.json`）+ 写回前台账快照 `scripts/ledger-before.json` 167KB + `.tmp-check/` 断言读数 44KB + 浏览器探针拷贝 `probe-*.html` 164KB。后两类里 **探针拷贝与交付 HTML 逐字节同源、`verify.sh` 每次重写**，已在仓库根 `.gitignore` 排除（见 §12），所以入库 486KB（探针拷贝不入库）。清理步骤几乎无事可做 —— 这与 12:00 轮删 119MB 是两个极端，说明「纯文本 + 零依赖」技能形态的收尾成本本身就是选它的一项收益。

12. **自指产物的读数不能写成字节精确值**（本条是收尾阶段才撞上的）：回填 `artifact_size` 时先写的是 `650,767B / 486,333B`，改完台账重跑 `verify.sh` —— 台账文本本身要进 `facts.json` 再进三份 .md，产物长了 89B，**于是我刚写进去的那两个字节数立刻变成假话**，页脚哈希同理换了两位。这类「描述自己的体积」的字段有不动点吗？没有，任何精度都会自抖。所以最终口径是**取整到 0.1KB**（抖动落在舍入位以下）+ 报告里的页脚哈希**只在台账彻底定稿后再抄、抄完不再动台账**。这条也正是 D6/CL10 staleness 判据的反面用法：判据防的是「台账改了、看板停在旧叙事」，而它同样会抓到「报告抄了旧哈希」。
