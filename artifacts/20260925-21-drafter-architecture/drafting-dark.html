02 · 阶段职责 READ / PICK / BUILD / CHECK / CLEAN / WRITE

01
读记忆 READ
work-log.md 全量 + state.json 结构化字段
不继承任何对话，判断只能来自磁盘
→ tried / used_styles
漏读 = 重复已试组合
02
选题 PICK
next_candidates 里 ★ 优先
找不到未试组合即留痕退出
→ 1 skill × 1 scenario
范围外溢是最常见失误
03
构建 BUILD
严格按被验技能的流程与规则出 3 个风格页
中间产物一律进 .tmp/ 与 node_modules/
→ artifacts/<run>/
技能规则冲突在此暴露
04
校验 CHECK
内联脚本先过 node vm 语法桩
布局与配色用计算样式断言，不靠肉眼
→ 断言 N/N
静默不渲染类缺陷唯一防线
05
收尾 CLEAN
删依赖 / 构建缓存 / 临时脚本 / /tmp 文件
被删脚本先抄进 reports 再删
→ < 50MB / 场景
失败轮同样必须收尾
06
回写 WRITE
reports/ + state.json + work-log.md 追加一行
commit 后走 SSH 推送
→ origin/main
HTTPS 通道不可用

04 · 环境不可假设项 DO NOT ASSUME

GitHub HTTPS 被 TLS 层重置 → 只走 git@github.com（实经 ssh.github.com:443），known_hosts 写进 .tmp/
npm 官方 registry 不可达 → registry.npmmirror.com；npx 会回落到不可达源，改用 ./node_modules/.bin/*
外部技能源 skills.sh / raw.githubusercontent 不可达；扩展市场安装需用户确认 → 无人值守轮只用 ~/.qoder-cn/skills/ 已装技能
浏览器面板 hidden 时 React 更新不落 DOM、innerWidth=0 使溢出断言假通过 → 交互断言走 jsdom，浏览器只留计算样式复核
计量 体积一律 Buffer.byteLength，不用 String.length（UTF-8 中文比 UTF-16 码元多 2%+）
实心 = 已完成 空心 = 未开始 实线 = 必经 虚线 = 边界 DRAFTING · REVERSED PALETTE · 偏离技能默认色板（见报告 §4）
