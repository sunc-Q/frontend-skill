3. 记忆文件 §3

records/work-log.md人读流水账，每轮一行，历史行不修改
state/state.json机读台账，7 个顶层字段
reports/<run>.md复现文档；被删脚本须转录
artifacts/<run>/仅最终可预览产物

4. 阶段规格 §4

  1. 读记忆 — 读全量 work-log 与 state 的 tried / used_styles / skills_seen / environment_notes / next_candidatesR1
  2. 选题 — 候选来源优先级：★ 排队项 > 本机 ~/.qoder-cn/skills/ 已装 > Web 检索；过 G1–G3
  3. 构建 — 按被验技能自身规则出 3 个风格页，中间产物只进 node_modules/、dist/、.tmp/
  4. 校验 — 内联脚本先 node vm 语法桩2；视觉差异用计算样式断言，不用肉眼
  5. 收尾 — 删依赖/缓存/临时脚本与 /tmp 文件；端口占用先 ps 核对命令行再 kill
  6. 记录推送 — 报告 → state → work-log 行 → commit → push 到 origin/main

5. 去重四道闸 §5

G1 组合tried[].skill + .scenario 命中即弃
G2 风格used_styles[] 不得出现，需 3 项全新
G3 来源已记不可用者不再探测
G4 产物须双击可开；ES Module 需内联

6. 无候选处置 §6

  • work-log 追加「本次无新组合可试」并写明卡点
  • state 不新增 tried 条目
  • 直接结束，仍须收尾清理

9. 技能规则符合性 §9

  • 扁平：无阴影、无渐变、无圆角按钮、无模糊
  • 描线：结构用 1–2px 实线，内容块白底
  • 单色基座：仅 1 处语义色（本页用于作废/修订标记）
  • 字体：标题无衬线，数据与代码等宽，全系统字体
  • 高数据墨水比：图示即信息，不含营销装饰

注 NOTES

  1. 不继承对话：任何「是否试过 / 能否用」的判断必须来自本轮读盘结果，不得凭技能名推断。
  2. 内联脚本语法错误会让整页静默不渲染且控制台无输出，故语法桩先于任何浏览器复核。
  3. 中文 UTF-8 字节数比 UTF-16 码元多 2% 以上，报告数字若按 String.length 计算将系统性偏小。
  4. 本规格页为三风格中的「印刷件」变体：三栏、A4 图号条、虚线键值表；与 21-A 单栏图纸、21-B 深色左索引版构成同技能风格能力横评。
